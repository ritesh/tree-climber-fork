# Query API for CFG and data-flow graphs (2026-10-13)

Tracks GitHub issue #47, part of the taint-tracking epic (#44). Every consumer of the graphs writes its own traversal over `CFG.nodes`; the prototype taint tracker in #44 is 40 lines of that. This adds one small, language-agnostic query layer, `tree_climber.query`.

## Scope

A new package `src/tree_climber/query/`. It only reads a `CFG` and the existing dataflow solvers; it changes no existing file except docs, so it merges cleanly with the interprocedural work (#46), which edits the CFG types, visitors and dataflow packages.

- **Lookup**: node by id, by text (substring, exact or regex), by `NodeType`, by enclosing function, the functions themselves, nodes calling a name (`callee` or `callee_text` of a call site, any of several names), nodes defining or using a variable.
- **Flow queries**: successors and predecessors with edge-kind filters, reachability (forward and backward), `can_reach`, all simple paths between two nodes with bounds, shortest path. Edge kinds are `flow` (unlabeled), `true`, `false`, `exception`, `function_call`, `function_return`. Filters are an allow-list (`labels`) and a deny-list (`exclude`); paths also take `avoid` (nodes a path may not pass through).
- **Data-flow queries**: `def_use(variable)` and `use_def(variable)` built on `RoundRobinSolver` + `ReachingDefinitionsProblem` + `DefUseSolver` / `UseDefSolver`; forward and backward slices from a node (optionally for one variable); shortest and bounded data-flow paths between two nodes.
- **Path result**: `Path` of `PathStep`s (node id, node type, text, kind of the edge that arrives at it, variable carried). `str()` for the terminal, `to_dict()` for JSON, frozen dataclasses for equality in tests.
- **networkx export**: `to_networkx()` gives a `MultiDiGraph` with the control edges, optionally the data-flow edges.
- **Docs**: "Querying the graph" in `docs/python-guide.md`; a line in the README architecture list.

## Design

- `CodeGraph.from_source(language, source)` / `CodeGraph.from_cfg(cfg)`. Built once; function membership is indexed at construction, solver results are computed on first use and cached. Node-returning queries return `CFGNode`s sorted by id; arguments accept an id or a `CFGNode`.
- **Function membership** follows the rule in `test/python_cfg/cfg_helpers.py`: the nodes reachable from an `ENTRY` without following `function_call` / `function_return`. A function is identified by its `ENTRY` node (names can repeat: overloads, methods of different classes).
- **Data-flow model.** The unit is a *fact* `(node, variable, is_definition)`. Edges: definition fact -> use fact for each def-use chain (kind `def_use`), and use fact -> every definition fact of the same node (statement granularity, the same approximation the def-use chains already make: a statement's definitions depend on all of its uses). Slices and data-flow paths are searches on this graph, forward or backward. Paths collapse the intra-node moves, so a step is a node and the edge into it is `def_use` (or an extra edge's kind) with the variable.
- **Extra flow edges** (extension point for #46): `DataFlowEdge(source, source_variable, target, target_variable, kind)`, frozen. Every data-flow query takes `extra_edges: Optional[Iterable[DataFlowEdge]]` and adds them to the fact graph for that call; nothing is stored. An edge leaves the facts at `source` named `source_variable`, and arrives at the definition fact `(target, target_variable)` if that variable is defined at `target`, and at the use fact if it is used there (both if both). A variable that is neither defined nor used at the node (a synthetic name such as a return value) is treated as node-wide: the edge leaves from every fact of the source node, and arrives as a use that influences every definition of the target. So an argument -> parameter edge is followed only when the argument variable is tainted, which is the precision #46 needs.
- Shortest data-flow path is a 0-1 BFS (intra-node moves cost 0), so "shortest" counts node hops.
- **Bounds.** `paths` / `data_flow_paths` enumerate simple paths depth first (successors in id order), stop at `max_paths` (default 100) and never exceed `max_length` edges (default: unbounded, which simple-path enumeration keeps finite). The search is pruned to nodes that can reach the target so a cycle cannot make it wander.
- Errors: unknown node id -> `KeyError`; a `variable` that the node neither defines nor uses -> `ValueError`; non-positive `max_paths` or negative `max_length` -> `ValueError`.

## Tests

`test/query/`, each query for Python, C and Java, with exact expectations on small inline programs, plus the existing `data_flow_patterns.py` fixture:

- lookup (id, text modes, type, function, calling by `callee` and `callee_text`, defining, using);
- successors / predecessors with every edge-kind filter (`flow`, `true`, `false`, `exception`, `function_call`, `function_return`), `labels` vs `exclude`;
- reachability both directions, `can_reach`, call edges followed or excluded;
- `paths`: all paths on a diamond, a loop (cycles do not hang), `max_paths`, `max_length` at the boundary, `avoid`, unreachable target, source = target; `shortest_path` including ties and filters;
- `def_use` / `use_def` agree with the solvers and with each other; loop-carried and branch merges;
- slices forward and backward, with a variable, without, and with hand-built extra edges (followed, variable-sensitive, synthetic variable, not followed when absent); `data_flow_path` / `data_flow_paths`;
- `Path`: `str()`, `to_dict()` round-trips through `json`, equality, accessors;
- networkx export: nodes, attributes, edge kinds, data layer;
- acceptance: the taint prototype rewritten against the API produces the same findings as the original on the fixture and on extra programs (source -> assignment -> sink found, reassignment kills, sanitizer blocks).

Mutation-checked with at least 15 deliberate bugs; results below.

## Results

Executive summary: `tree_climber.query` is in. One `CodeGraph` answers the lookup, flow, data-flow and slice questions for C, Java and Python, returns `Path` objects that print, serialise and compare, and exports to networkx. The taint prototype from #44 is now a seven-line loop over `calling()` and `data_flow_path()`. No existing file under `src/` was changed. `ruff format --check`, `ruff check`, `pyright` and `pytest` pass (1282 passed, 20 strict xfails; the 336 new tests are in `test/query/`).

### What was built
- `edges.py` (kind constants, `CALL_KINDS`, `DataFlowEdge`), `path.py` (`Path`, `PathStep`), `facts.py` (the fact graph behind slices and data-flow paths), `graph.py` (`CodeGraph`), `__init__.py`.
- API: `CodeGraph.from_source` / `from_cfg`; `node`, `nodes`, `by_text`, `by_type`, `calling`, `defining`, `using`, `functions`, `function_of`, `function_nodes`; `successors`, `predecessors`, `edge_kind`, `reachable` (`backward=`), `can_reach`, `shortest_path`, `paths`; `def_use`, `use_def`, `data_flow_edges`, `forward_slice`, `backward_slice`, `data_flow_path`, `data_flow_paths`; `to_networkx`.
- Not in the plan, added while writing: `data_flow_paths` (bounded enumeration on the fact graph, sharing the bounds of `paths`), `edge_kind`, `data_flow_edges`.

### What was verified
- Tests: the same program in Python, C and Java for every query (the node ids are identical across the three, so expectations are written in roles such as `src`, `sink`, `acc`), plus exception edges (Python only: the C and Java visitors have none), overloads, dead code, methods, 12- and 25-diamond graphs for the bounds, and two perf guards (an unreachable target behind 2^25 simple paths, in the CFG and in the data flow).
- Differential checks: `can_reach` and `shortest_path` length equal `networkx.has_path` / `shortest_path_length` for every node pair in all three programs; `forward_slice` / `backward_slice` of every node equal `networkx.descendants` / `ancestors` of the data layer; `def_use` / `use_def` equal the solvers' chains and are each other's inverse; the prototype taint tracker (kept in the test file) and the rewrite report the same source/sink pairs on 16 programs and on `data_flow_patterns.py`, and the rewrite's paths are a subset of the prototype's.
- The documentation examples were run and their output pasted; `test_query_guide.py` pins them.
- Mutation check: 76 deliberate bugs, one at a time, restoring the file after each and checking the working tree. Wrong filter polarity (labels and exclude, for successors, predecessors, reachability, shortest path and paths), unlabeled-edge kind, predecessor label read from the wrong end, forward/backward swapped (steps and slices), start dropped from reachability, DFS instead of BFS, path order reversed, node order descending, `avoid` applied to the ends and ignored, off-by-one in `max_length` (CFG and data flow) and `max_paths` (CFG and data flow), bound validation, allowing revisits in cycles, pruning removed, `can_reach` inverted, function membership across calls, `calling` ignoring `callee_text` or `function_calls`, `by_type` case, exact vs substring, regex `match` vs `search`, extra edges listed under the wrong variable, no dedupe of extra edges, slice criterion dropped, variable ignored, intra-node moves shown as steps, networkx layers and kinds, statement mixing removed, def-use direction swapped, node-wide source and arrival rules for names that are not variables, definition-only or use-only arrival, step cost counting in-node moves, `Path` accessors and text rendering, JSON keys, empty seeds. 71 were caught by the first run. 5 survived: 2 were killed by new tests (first-step `labels` / `exclude` in `paths`; key order of `def_use` / `use_def`, tested by reversing the solver's chain order) and 3 are equivalent (below). Three of the catches are hangs (removing the visited-node check or the pruning makes the search run for ever), which the runner counted as caught after a 60 s timeout.
- One real bug was found by a test I wrote after the mutation rounds: a data-flow path from a node with no variables (an `ENTRY`) raised `IndexError`; fixed and covered.

### Equivalent mutants
- `function_of` using assignment instead of `setdefault`: a node is reachable from exactly one entry, so the order cannot matter.
- Zero-cost moves put at the back of the queue instead of the front in `FactGraph.shortest`: moves inside a node are only use -> definition, so a zero-cost chain has length one and FIFO order finds the same costs. I kept the 0-1 form so a future longer chain of free moves stays correct.
- `calling` also adding `site.callee`: it is always in `function_calls`, so I removed the redundant code instead.

### Behavior to know and approximations
- The data-flow model is statement-level (all uses of a statement flow into all of its definitions), the same approximation the def-use chains make. Slices have no control dependence. Flow queries follow call and return edges unless excluded and are not call/return-matched, and calls are linked by name, as everywhere else.
- Extra edges follow the variable they name; a name that the node neither defines nor uses applies to the whole node (a return-value placeholder works). This is the extension point for #46: it only needs to produce `DataFlowEdge`s.
- `paths` / `data_flow_paths` are depth first, return at most `max_paths` (default 100) and give no signal when they stop early.
- `functions()` of a Python file with only `def`s has no `<module>` entry, as in the CFG.
- Java and C produce no `exception` edges today, so that filter is exercised for Python only.
- Not verified: other versions of networkx than the locked 3.5, and any large real-world graph (the largest input is a 25-diamond chain, under 100 nodes).
